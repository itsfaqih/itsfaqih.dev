## Commit Message Standards

- Commit messages must describe the actual change, not the action of committing.
- Avoid generic messages such as `update files`, `misc fixes`, or `remaining changes`.
- Use this format:
  - `<type>: <specific summary>`
- Recommended types: `feat`, `fix`, `refactor`, `style`, `docs`, `test`, `chore`.
- The summary must mention what changed and where when relevant.
  - Good: `style: switch root font to sans and remove frosted theme toggle styles`
  - Bad: `chore: commit remaining UI updates`
- If needed, add a body with 1-3 bullets for key file-level changes.
