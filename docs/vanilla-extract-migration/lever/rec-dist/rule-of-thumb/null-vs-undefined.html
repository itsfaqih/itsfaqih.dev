Null vs Undefined

Use undefined for a value nobody gave, and null for one emptied on purpose.

Send null to clear a field. Leave a field out to keep it.

MISSINGEMPTY
IMPLICIT→EXPLICIT

Keep missing and empty apart

Give undefined and null one meaning each, so no code has to guess which it got.

Tell missing from empty

Read undefined to mean nobody gave a value. Read null to mean someone checked and found nothing. Ana skipped the phone question. Bo said he has no phone. If you send both as null, no code can tell them apart.

Try it
Quiz

Fields you asked for

The client asked for ?fields=name,manager. Bo has no manager. Nobody asked for his phone. Pick the key to leave out.

Drag the piece into the code. Or tap it, then tap a spot.

  • {
  • "name": "Bo",
  • "manager":
  • "phone":

Mark optional with ?:

Leave a skipped value undefined. If you type it with ?:, callers can leave it out. If you type it | null, callers with no value must pass null.

Try it

A skippable field

Signing up, people may skip the nickname, and most callers never have one. Place ?: string.

Drag the piece into the code. Or tap it, then tap a spot.

  • type SignUp = {
  • email
  • nickname
  • password
  • }

Clear with null

When the user empties a field, send null. JSON drops keys set to undefined, so that clear never reaches the server.

Try it

The date picker

The user cleared the due date and never opened the assignee or notes. Place null.

Drag the piece into the code. Or tap it, then tap a spot.

  • patch("/tasks/12", {
  • title: "Ship v2",
  • assignee:
  • due:
  • notes:
  • })

Leave untouched fields out

A PATCH changes only the fields it carries. If you fill a draft with null, every untouched field goes out as a clear. Start it empty so only the changes go out.

Try it
Quiz

Only the title

The user renamed the task and removed its reviewer. They didn't touch the due date. Place undefined.

Drag the piece into the code. Or tap it, then tap a spot.

  • const changes = {
  • title:
  • reviewer:
  • due:
  • }
  • patch("/tasks/12", changes)
Your piece

Force the decision

?: lets a caller skip a field silently. When every caller must decide, make it required and nullable. A caller who leaves it out gets a type error, and "nobody" is a null someone wrote on purpose.

Try it
Quiz

A new task

Every new task must name an assignee or say there's none. The colour is optional and falls back to grey. Place | null.

Drag the piece into the code. Or tap it, then tap a spot.

  • type NewTask = {
  • title: string
  • assignee: User
  • color?: string
  • }
Your piece

Return null for not found

Return null from a lookup that finds nothing. Map.get returns undefined, and JSON.stringify turns that into no body.

Try it
Quiz

Two sign-ups

You looked up bo@x.io and nobody has that email. You haven't looked up cy@x.io yet. Place null.

TL;DR

  1. Declared, not assigned yetLeave it undefined
  2. An argument the caller may skipType it name?: string
  3. The user cleared a fieldSet it to null
  4. A field the user didn't touchLeave it out of the request
  5. A field every caller must decideType it T | null, not ?:
  6. A lookup that found nothingReturn null
